# BallWise — sprawdzenie aplikacji, 16 listopada 2026

Zakres: silnik i wykonanie treningu, konto, Fuel, czytelność ekranów oraz
lokalne sprawdzenie aplikacji web. Punktem wyjścia jest commit
`c806340039158082e3d629f7a9dd17eac1f09767`. Publikacja sklepu Apple nie jest
celem tego etapu.

## Naprawione zachowanie

- Rejestracja respektuje istniejący próg nowych kont 16+. Dotychczasowe konta
  młodszych zawodników pozostają obsługiwane.
- Odświeżenie edycji onboardingu czeka na zapisany profil, zamiast inicjalizować
  pusty formularz. Błąd odczytu daje możliwość ponowienia.
- Edycja profilu zachowuje alergie, nietolerancje i zwykłe wykluczenia Fuel;
  cofnięcie zgody nadal usuwa dane zależne od zgody zdrowotnej.
- Przedmeczowy Fuel wybiera posiłek według rzeczywistej godziny zjedzenia,
  niezależnie od kolejności dopisania/importu. Pomija przyszłe wpisy i respektuje
  późniejszą odpowiedź o ostatnim posiłku.
- Pominięcia w regeneracji odnoszą się do ćwiczeń, także gdy ćwiczenie ma kroki
  na obie strony i przerwy. Wyciszenie zapisuje wykonane i pominięte ćwiczenia
  osobno; błąd zapisu zatrzymuje zakończenie i pozwala ponowić zapis.
- Sesja oznaczona „Dziś nie mogę” pozostaje podglądem z czytelnym wyjaśnieniem.
  Nie oferuje niedziałającego startu i nie wymusza aktualizacji samej pominiętej
  receptury. Nierozpoczęta druga sesja nadal podlega kontroli aktualności.
- Profil przy szerokości poniżej 360 px układa etykietę nad wartością, żeby
  długie nazwy poziomu i ligi nie łamały się w środku słów.
- Przygotowanie projektu iOS wykrywa rozbieżny Bundle ID i dopina entitlements
  dla obu konfiguracji. Opisy kamery i lokalnego zapisu GPS odpowiadają kodowi;
  nie deklaruje się wykonania kompilacji Xcode.

## Dowody lokalne

- Pełny Vitest: **330 plików, 2807 testów PASS, 1 test warunkowo pominięty**
  w strefie UTC. Testy jednostkowe i lokalne harnessy SQL mają blokadę
  przypadkowych połączeń z hostowanym backendem.
- Końcowe sprawdzenie zmienionych przepływów sesji i dat w strefie
  `Europe/Warsaw`: **4 pliki, 37 testów PASS**, w tym test pominięty w UTC.
- Końcowy TypeScript, ESLint oraz build web i mobilnego SPA: **PASS**. Lockfile'e npm i Bun są
  zgodne; zależności zainstalowano przez czyste `npm ci`.
- Nawigacja w Chromium: podgląd → instrukcja → pojedynczy start → tabela
  serii → tygodniowy Plan → Start → Fuel → historia Postępu → bieżące IQ 5×5
  → Lab → podgląd przyszłej sesji. Dokładnie jeden start, brak zewnętrznych
  żądań i błędów JS; brak poziomego przepełnienia przy 390 px oraz 320 px
  z tekstem powiększonym do 200%.
- Tablica Football IQ: **19 widoków/scenariuszy PASS**, prawdziwy renderer 3D,
  własny ruch i podanie, wynik, odtwarzanie, przejęcie decyzji partnera,
  tryb samodzielny oraz widok zastępczy po zablokowaniu rzeczywistego pliku GLB.
  Pięć rozmiarów ekranu, w tym orientacja pozioma.
- Mobilne SPA: wejście gościa na `/start` prowadzi do logowania przy
  320/390/1280 px. Demo, FAQ, polityka prywatności, regulamin i prawa do danych
  otwierają się bez błędów JS i poziomego przepełnienia. Żądania zewnętrzne
  były blokowane; nie wykonywano zapisów konta.
- Profil: świeży podgląd 320 i 390 px bez przepełnienia i dodatkowych
  kontenerów przewijania. Sprawdzono również układ Lab, sprintu i siły.

Nawigacja i ekrany zalogowane korzystają z izolowanych adapterów oraz
autorskich danych testowych. Potwierdzają zachowanie UI, nie działanie konta
w hostowanym Supabase ani pomiar na fizycznym telefonie.

## Powtórzenie sprawdzenia

```sh
npm ci
npm run verify:release
TZ=Europe/Warsaw npx vitest run src/lib/loadwise/todayIso.test.ts
```

Scenariusze przeglądarkowe wymagają lokalnego pakietu Playwright oraz Chromium.
Można wskazać je przez `BALLWISE_PLAYWRIGHT_PACKAGE` i
`BALLWISE_CHROMIUM_EXECUTABLE`:

```sh
node scripts/check-design-ui.mjs --navigation-only
node scripts/check-iq-ui.mjs
```
